# 🔴 SSHDeck v0.1.0_beta.1 — Windows Beta

> **PRE-RELEASE / BETA**  
> This build is intended for early testing and real-world feedback. Windows x64 is the verified runtime target for this release. The executable is currently unsigned, so Windows SmartScreen may display a warning.

SSHDeck `v0.1.0_beta.1` is a maintenance refresh of the first public beta and is published from the current reviewed `main` release snapshot. It preserves the original `v0.1.0_beta` tag unchanged while giving the current `main` state its own explicit GitHub prerelease, Windows binary, and SHA-256 checksum.

## Why beta.1 exists

The original `v0.1.0_beta` remains an immutable historical snapshot. After that beta was created, the repository received release-pipeline improvements and a history-reconciliation commit that restored the feature-level Phase 0–8 development graph to `main` without changing SSHDeck runtime behavior.

`v0.1.0_beta.1` therefore provides a clean release point for the current `main` state:

- the tag is created from the reviewed release snapshot;
- the Windows executable is built from that exact tag;
- GitHub Release metadata and the binary refer to the same version;
- `SHA256SUMS.txt` is published alongside the executable;
- the original `v0.1.0_beta` tag and release remain available for historical comparison.

## What is included

### SSH workspace

- real PTY-backed SSH terminal sessions powered by the system OpenSSH client;
- multiple session tabs with selection and lifecycle state;
- active, reconnecting, disconnected and failed session states;
- manual reconnect and configurable auto-reconnect;
- session duration, exit code and signal diagnostics;
- keyboard session navigation and shared command routing;
- existing OpenSSH behavior remains authoritative, including `ssh-agent`, `known_hosts`, `IdentityFile`, aliases and compatible config options.

### Server registry

- SSHDeck-local server registry instead of silently rewriting `~/.ssh/config`;
- Add Server and Edit Server workflows;
- favorites and groups;
- search and filtering;
- OpenSSH config import;
- explicit OpenSSH config export;
- server connection status and diagnostics;
- TCP latency, SSH handshake visibility and remote uptime when available.

### Remote Files / SFTP

- remote directory browsing through the system `sftp` client;
- path navigation;
- directory creation;
- rename;
- file delete;
- upload and download;
- staged TCP → SSH → SFTP diagnostics when connection setup fails;
- SSH-service error classification for banner/KEX/remote-close/reset failures.

SSHDeck intentionally keeps a conservative OpenSSH batch-mode boundary for automated SFTP operations. Password-only automated SFTP is therefore not supported in this beta.

### Transfers

- global transfer queue;
- bounded concurrent transfers;
- queued, running, done, failed and cancelled states;
- progress information;
- transfer speed;
- ETA where calculable;
- cancel;
- retry;
- clear completed entries;
- shared transfer state across the workbench.

### Port forwarding

- Local forwarding (`ssh -L`);
- Remote forwarding (`ssh -R`);
- Dynamic/SOCKS forwarding (`ssh -D`);
- start and stop lifecycle;
- delete and edit when stopped;
- auto-restart support;
- status and diagnostics;
- synchronized state across Ports workspace, Inspector and Bottom Panel.

### Sessions and History

- dedicated Sessions workspace;
- All / Active / Issues session views;
- focus, reconnect and close actions;
- auto-reconnect controls;
- persisted connection History;
- bounded history retention;
- history search/filtering;
- reconnect from a history record;
- safe history clearing.

### Structured Logs

- SSH/session lifecycle events;
- reconnect events;
- tunnel events;
- transfer events;
- completed SFTP diagnostic events;
- bounded in-memory log retention;
- centralized redaction for passwords, passphrases, tokens, Authorization values and private-key material;

### Workbench Search

Search spans the real workspace state, including:

- transfers;
- Quick Commands;

Search results route through the same command paths used by the Activity Bar, menus and Command Palette.

### Settings

- rejection of unsupported future schema versions;
- default auto-reconnect setting;
- diagnostics timeout configuration;
- transfer concurrency configuration;
- Quick Command safety level;

### Navigation and command consistency

- Activity Bar destinations are functional;
- Bottom Panel Ports / Logs / Transfers tabs contain real behavior/data;
- Command Palette exposes the same command model;
- keyboard shortcuts use shared command routing;
- app/View menus route through the same commands;

- Windows 10/11 x64;

## Security model

SSHDeck is local-first and deliberately builds on the system OpenSSH toolchain rather than implementing a separate proprietary SSH protocol stack.

Important beta security properties include:

- OpenSSH remains responsible for the underlying SSH connection behavior;
- SSHDeck does not silently overwrite the user's OpenSSH config as part of normal server editing;
- OpenSSH import/export is explicit;
- structured logs redact common secret/key material;
- Quick Commands classify dangerous commands and can require confirmation;
- automated SFTP keeps the OpenSSH batch-mode safety boundary.

## Known beta limitations

This is not a stable `1.0` release.

Current limitations include:

- Windows x64 is the verified release target;
- Linux/macOS release packaging is not yet part of the verified matrix;
- the Windows binary is unsigned;
- SmartScreen may warn on first launch;
- recursive SFTP directory upload/download/delete is not implemented;
- password-only automated SFTP is not supported;
- settings/workspace schemas may evolve before stable `v1.0.0`;
- installer packaging and code signing are future release work.

## Release provenance

`v0.1.0_beta.1` is intended to represent the current reviewed `main` release snapshot at publication time. The release workflow creates the tag first, checks out that exact tag, and only then builds the Windows executable. This prevents the published binary from drifting away from the Git tag used by the GitHub Release.

The previous `v0.1.0_beta` remains preserved and is not retagged or rewritten.

## Feedback

When reporting a beta problem, useful details include:

- Windows version;
- SSHDeck release version;
- whether the issue is SSH, SFTP, Transfers, Ports, Sessions, Logs, Search or Settings related;
- the relevant non-sensitive diagnostic text;
- exact reproduction steps;
- whether the same target works with the system `ssh`/`sftp` commands directly.

Do not include passwords, private keys, access tokens or other credentials in public issue reports.
