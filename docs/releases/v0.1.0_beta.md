# 🔴 SSHDeck v0.1.0_beta — Windows Beta

> **PRE-RELEASE / BETA**  
> This build is intended for early testing and real-world feedback. Windows is the verified runtime target for this release. The binary is currently unsigned, so Windows SmartScreen may show a warning.

SSHDeck `v0.1.0_beta` is the first public beta of SSHDeck: a fast, local-first desktop SSH workspace built around the system OpenSSH toolchain instead of replacing it with a proprietary SSH stack.

The beta milestone focuses on making the desktop experience feel like a complete SSH workbench: real terminal sessions, remote files, transfers, tunnels, session management, diagnostics, search, settings, and consistent navigation all share the same underlying lifecycle/state paths.

## What is included

### SSH workspace

- real PTY-backed SSH terminal sessions powered by system OpenSSH;
- multiple session tabs;
- active / reconnecting / disconnected / failed lifecycle states;
- manual reconnect and configurable auto-reconnect;
- session duration, exit code and signal diagnostics;
- keyboard session navigation and selection shortcuts;
- existing `ssh-agent`, `known_hosts`, `IdentityFile`, `ProxyJump`, host aliases and other OpenSSH behavior remain authoritative.

### Server registry

- local SSHDeck server registry;
- Add / Edit / Delete server;
- favorites and groups;
- server filtering and recent targets;
- import literal hosts from OpenSSH configuration through `ssh -G`;
- safe OpenSSH snippet export without silently rewriting `~/.ssh/config`;
- connection status, latency, authentication state and Linux uptime probes where available.

### Remote Files / SFTP

- SFTP browser backed by the system `sftp` client;
- remote directory navigation;
- create directory;
- rename;
- file delete and guarded directory delete behavior;
- upload and download;
- staged diagnostics: TCP → SSH → SFTP;
- detailed failure classification for unreachable hosts, SSH service problems, authentication and SFTP startup failures.

### Transfers

- global in-memory transfer queue;
- queued / running / done / failed / cancelled states;
- progress, throughput and ETA;
- cancel and retry;
- configurable transfer concurrency;
- one shared TransferManager instead of per-view transfer workers.

### Port forwarding

- Local forwarding (`ssh -L`);
- Remote forwarding (`ssh -R`);
- Dynamic / SOCKS forwarding (`ssh -D`);
- Add / Edit / Delete tunnel;
- Start / Stop;
- process state, duration and stderr/exit diagnostics;
- bounded auto-restart with backoff;
- shared tunnel lifecycle across Ports Workspace, Bottom Panel and Inspector.

### Sessions and History

- dedicated Sessions workspace;
- filtering for active and problematic sessions;
- synchronized selection with terminal tabs;
- persisted connection history;
- history filtering by server and outcome;
- timestamps, duration, exit code and signal;
- reconnect from historical entries when the target server still exists;
- confirmed history clearing;
- bounded history retention.

### Structured Logs / Diagnostics

- structured in-memory Workbench event log;
- lifecycle events for SSH sessions, reconnects, tunnels, transfers and completed SFTP diagnostics;
- severity/source filters and search;
- bounded log retention;
- centralized redaction of password/token/private-key-like material;
- raw terminal output and password prompts are intentionally not copied into structured logs.

### Workbench Search

Unified search across:

- Servers;
- Sessions;
- History;
- Ports / tunnels;
- Transfers;
- Quick Commands;
- SSHDeck application commands.

Search actions route through the same providers and CommandService used by the rest of the Workbench instead of creating separate state or lifecycle owners.

### Settings

Versioned settings are persisted in `workspace.json` with validation/migration support.

Current functional settings include:

- default auto-reconnect behavior;
- SSH/SFTP diagnostic timeout;
- transfer concurrency;
- Quick Command safety policy: Standard / Strict;
- workspace layout restore behavior.

### Command safety

Saved Quick Commands have local risk classification.

- **Standard** — low-risk commands can run normally; medium/high/critical commands require confirmation;
- **Strict** — every Quick Command requires confirmation;
- critical commands additionally require typing `RUN`;
- SSHDeck intentionally does not intercept text manually typed into the real terminal.

## Security model

SSHDeck deliberately keeps OpenSSH as the authentication and host-verification authority.

- private keys are not imported into an SSHDeck-managed key store;
- `known_hosts` verification is not bypassed;
- passwords used for interactive sessions remain process-memory-only and are not written into the SSHDeck registry;
- structured logs do not intentionally record raw terminal/password-prompt output;
- credential-like values and private-key material are redacted from structured diagnostics;
- destructive Quick Commands require explicit confirmation according to the configured safety policy.

## Known beta limitations

- **Windows only is verified for this release.** Linux/macOS source builds may work, but packaging/release gates are not yet part of the supported matrix.
- the Windows executable is currently **unsigned**; SmartScreen may warn on first launch;
- SFTP directory transfer/delete workflows are intentionally non-recursive;
- password-only automated SFTP is not supported because the SFTP automation path keeps OpenSSH batch-mode safety boundaries;
- the settings/workspace persistence schema may still evolve before stable `v1.0.0`;
- installer packaging and code signing are planned for later releases.
